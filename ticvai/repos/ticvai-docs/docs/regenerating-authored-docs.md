# Regenerating the hand-authored docs after a contract change

> Companion to [`contract-change-runbook.md`](contract-change-runbook.md). That file says what a
> contract edit sets off; this one says how to rebuild the parts no tool rebuilds — ring 4.

## What feeds what

```
contracts/*.yaml ──┬─> derive-lineage.py --apply ──> api-data-lineage.json   <- FIRST, always
                   ├─> derive-domain.py ──> domain-markers.json
                   ├─> derive-schema.py ──> schema-reference.json
                   └─> build-audience.py ──> audience-index.json

api-data-lineage.json ──> 20+ tools, including build-audience.py
handoff/links.json ──> derive-domain.py            (an INPUT; nothing writes it)
service-decomposition.json ──┬─> derive-diagrams.py
                             ├─> derive-burst-scope.py
                             ├─> build-schema-workbook.py
                             ├─> build-services-workbook.py
                             └─> check-package.py

traceability.json ──> build-status.py ──> status.json
contract-backlog.json ──> build-backlog-index.py ──> docs/registers/contract-backlog.md
backlog-clusters.json ──> build-cluster-index.py ──> docs/registers/clusters.md
docs/registers/conflicts.md ──> build-cf-index.py ──> conflict-status.md
```

**Everything on the left of an arrow below the first block is an authored input.** Nothing in
`tools/` writes `service-decomposition.json`, `links.json`, `traceability.json`,
`contract-backlog.json` or `backlog-clusters.json` — nor the five documents below. Nine files
in total; see ring 4 of the contract-change runbook.

---

**These five are not generated by any tool.** They were written by reading the contracts, so
when a contract changes they go stale silently — nothing fails, no checker complains, and the
next person reads a document that is wrong. `api-list.md` currently claims *581 published* and
marks modules blocked; the package has **1,974 operations across 32 contracts and nothing blocked.**

Paste one prompt per session into Claude Code from the repo root. **Do them one at a time** —
each needs the contracts read carefully, and batching produces summaries rather than documents.

---

## House style — prepend to any of these

```
House style for this repo: terse and evidence-first. State what is true and name the operation,
schema or ADR that proves it. No hedging, no marketing language, no "it is worth noting".
Bold the claim, not the label. Where a design choice looks odd, give the reason in one line —
the existing docs do this well, e.g. "a deposit box is allocated to a cashier, not a till".
Never restate a heading in its first sentence. Do not invent counts: derive every number from
the files and say how you derived it.
```

---

## 1. `handoff/api-list.md` — most stale, do first

```
Regenerate handoff/api-list.md from the current contracts.

Read every file in contracts/spine/, contracts/satellite/ and contracts/shared/. For each,
count operations (get/post/put/patch/delete under paths) and read the info.description.

Produce one section per contract, ordered spine then satellite then shared, each giving:
the contract file, its operation count, what it owns in one line, and the three or four
operations a new engineer would need first. Open with a total and the spine/satellite split.

Do not carry over any status marker from the existing file — every module is built. Verify
your total against: python3 -c "import yaml,glob; print(sum(1 for f in glob.glob('contracts/*/*.yaml') for p,m in (yaml.safe_load(open(f)).get('paths') or {}).items() for v in m if v in ('get','post','put','patch','delete')))"
Expect 1,974 across 32 contracts (34 files: 9 spine, 23 satellite, 2 shared).
Note: handoff/api-data-lineage.json holds 1,981 because --apply never removes; the 7
extra are release* entries orphaned by the 8 September relinquish* rename.
```

## 2. `handoff/rag-index-sources.md` — check the events still exist

```
Verify and update handoff/rag-index-sources.md against the current contracts.

It declares eleven RAG index sources, each naming a table, the fields carrying retrievable
text, the collection it lands in, and the domain event that invalidates it. check-package.py
reads this file, so an error here fails a validator.

For each source confirm: the table still exists in x-ticvai-persistence, the named fields are
still present, and the invalidating event is still declared in events/. The file's own section
"Six events these sources need and that do not exist yet" must be re-derived — some may now
exist. Report what changed before writing, then write.
```

## 3. `handoff/artefact-audit.md` — supersede rather than patch

```
Rewrite handoff/artefact-audit.md. It is dated 17 August and predates the requirement walk,
which is now complete at 3,184 of 3,184 rows.

It classifies requirements by the kind of artefact each needs, and identifies which artefact
classes the package lacks. Re-derive from handoff/closed_classes.json and the current package,
and reconcile against handoff/traceability.json, handoff/contract-backlog.json and
handoff/backlog-clusters.json — the walk has since answered several of its open questions and
raised others.

Keep its two strongest findings if they still hold: that most configuration requirements do
not state a scope level, and that retention requirements state contradictory periods (the walk
found five different ones — see CF-64). Mark the file's date as the day you rewrite it.
```

## 4. `wireframes/LINKAGE.md` — counts drift every time a board changes

```
Update wireframes/LINKAGE.md against the current wireframes and screen definitions.

It documents how boards, screen YAML definitions and contract operations resolve to each other
in both directions, and which checker enforces it. Re-derive every count from the files:
number of boards, screens drawn, screens defined, and any drawn-but-undefined or
defined-but-undrawn. Run tools/check-wireframes.py and tools/check-screens.py and make the
document agree with what they report. Do not change the explanation of the chain unless the
chain itself changed.
```

## 5. `handoff/schema-viewer-notes.md` — only if the schema changed

```
Check whether handoff/schema-viewer-notes.md is still accurate.

It explains why the schema graph mis-navigates — clicking a catalogue table takes you to
platform — and proposes three kinds of edge as the fix. Run tools/derive-schema.py and inspect
handoff/schema-reference.json. If the cross-contract reference pattern it describes is
unchanged, leave the file alone and say so. Only rewrite if the underlying data changed.
```

---

## After any of them

```
bash tools/refresh.sh
```

All 24 checkers in the refresh's closing block must pass. `check-package.py` reads `rag-index-sources.md`, so #2 can fail
it directly; the others are narrative and will not fail a checker, **which is exactly why they
drift.**

## If you also changed x-ticvai-persistence

```
python3 tools/derive-schema.py && python3 tools/derive-domain.py && bash tools/refresh.sh
```

## 6. `handoff/service-decomposition.json` — a decision, not a prompt

**This one cannot be regenerated by reading the contracts, and it has the widest blast radius of
the nine.** Its note still reads *"How 28 contracts and 378 tables become 16 deployable
services"*; there are now 32 and 556, and `rental` and `accreditation` appear in it nowhere.
`derive-diagrams`, `derive-burst-scope`, both workbooks and `check-package` all read it, so a
contract missing from it is missing from the service topology **while every checker passes**.

Assigning a contract to a deployable service is a deployment decision, not a contract fact — the
same reason `derive-lineage` is additive-only. It needs a person to answer "where does this
deploy?" and then the five tools above re-run. `derive-lineage`'s own `NEW_CONTRACT_SERVICE` map
carries the working assumption: rental -> VenueOpsService, wallet -> RetailService,
payments -> OrderService, accreditation -> AccessService.

## Worth knowing

**Staleness in these nine used to be undetectable.** Every other checker validates structure and
cross-references; none compares a narrative document against the contracts it describes.
`tools/check-authored-inputs.py` now closes that: it compares each of the nine against the newest
file in `contracts/` and tests `service-decomposition.json`'s own note against the real contract
and table counts. It reports; it cannot fix, because none of these can be derived.

A stronger version would record in each file's front matter the hash of `contracts/` it was
written against, and warn when the hash moves — mtime says *something* changed, a hash says
*this* changed.
