# Board audit — 7 September 2026 · reconciled v2

Supersedes the v1 figures in this file. v1 counted `board-data.js`'s `platforms` array as
boarded screens; `atlas/BOARD-GAP-HANDOVER.md` counted only its `modules` array. Both are
partial, and the disagreement is entirely explained by which of the two arrays each side read.

`board-data.js` carries **two independent inventories**, and nothing in the file says they
mean different things:

| | What it is | Screens | Links out |
|---|---|---|---|
| `modules` | Boards drawn at pack fidelity | 813 | Yes — `<a href>` per screen |
| `platforms` | Generated frame inventory, one entry per package screen | 500 | **No** — the index renders `{{ s.href }}` and the platform screens carry no `href` |

The index's own header calls the second one *"platform boards · generated · scaffolded, not
drawn at pack fidelity."* **The handover is right and v1 was wrong: a generated frame is not
a board.** None of the fifteen `P0x …dc.html` files in `platforms` exists in this project.

## 2. §7 of the handover — the sixteenth platform does not exist

The package defines **fifteen** platforms and the board's `platforms` array carries **exactly
those fifteen**: P01, P02, P04–P16. The skipped code is **P03**, and it is skipped in the
package too — there is no `screens/P03-*.yaml` and no board references a `P03` anything.
`check-package` rule 12 has nothing to catch. **No board-side platform is unbacked.**

The `gm` half of §7 is confirmed: 40 `GM-1A…GM-8E` codes, none in `_id-register.yaml`, which
is why P02 reads 51 of 71.

## 3. Two things v1 found that the handover does not cover

**The generated count disagrees with itself.** The index header states **404** generated
platform frames. The `platforms` array sums to **500**. One of the two was written by hand.

**The `modules` index is stale against `platforms` on three platforms** — P01 44 vs 46,
P04 18 vs 24, P06 45 vs 66. The handover reads the low number in each case, which is why its
P01 line says 45 where the package says 46.
