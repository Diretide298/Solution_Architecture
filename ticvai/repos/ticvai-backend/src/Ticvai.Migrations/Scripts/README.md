# This folder held the August migration series, and it is empty on purpose

**The six `V000*.sql` files here were deleted on 21 September.** They were the
25 August generation — `V0001__baseline`, `V0001a__pii`, `V0002__identity`,
`V0003__tenancy`, `V0003a__scope-typing`, `V0003b__guest-facing`, 39 tables —
and they are the set `backend/README.md` records from the 31 August incident,
where *"the August definition won every time"*. That README says plainly: **if
you hold an older series, delete it.**

## Where the schema is now

`ticvai/backend/`, generated by `tools/derive-ddl.py` and applied in numeric
order by `backend/provision-tenant.sh`. The file order is the apply order:

    001-extensions.sql            ltree, btree_gist, pgcrypto
    002-migration-register.sql    platform.schema_version
    010-<schema>.sql              624 tables, one file per schema
    900-foreign-keys.sql          632 references
    910-indexes.sql               734 indexes
    920-row-level-security.sql    310 tables, default-deny, FORCE
    930-partitioning.sql          the venue partition helper

The row-level security, the extensions and the partition helper used to live in
a hand-written `V0001__baseline.sql` outside the numbered series, which is what
made two generations possible in the first place — **a `V*.sql` sorts after
`010-` and would have applied last.** They are generated with everything else
now.

## What is left here, and what is wrong with it

**The file you are reading replaced an unrelated one.** Until 21 September this
was a copy of the `docs/active/` index — sprint board, client agenda, this
week's blockers — which had landed in a folder of SQL scripts and stayed there.

**`Ticvai.Migrations` does not build, and did not before any of this.** It is
`<OutputType>Exe</OutputType>` with no `Program.cs` in the project at all, and
its only other content is `<EmbeddedResource Include="Scripts/*.sql" />`, which
now matches nothing. It is still listed in `Ticvai.sln`.

**That is a decision, not a defect to patch quietly.** Either the runner gets
written — a migration applier that reads the generated series — or the project
comes out of the solution, because the DDL is applied by a shell script today
and a project that claims to apply it and cannot is the more misleading of the
two.
