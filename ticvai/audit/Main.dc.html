Recurring and redundant screens

The inventory holds 492 screens. Read by the operations they call rather than the names they carry, they resolve to 373 distinct behaviours — so 105 screens do exactly what another screen already does, and 134 sit in pairs sharing four fifths of their operations. The duplication is not evenly spread: it clusters on eight workspaces that were re-drawn once per platform.

How this was measured

Every screen was reduced to the set of contract operations it declares. Two screens with the same set are the same screen: they read the same data, offer the same actions, and will need the same states. Name and platform were ignored, so nothing here rests on two screens happening to be called the same thing.

What is not redundancy

A screen repeated because the context genuinely differs stays. The scanner's offline journal is not the back office's scan activity: one is written with no network on a device held in one hand, the other is read at a desk. Same operations, different failure mode — and the failure mode is the design.

The test applied throughout: would one screen with a parameter serve both people on both devices? Where the answer is no, the pair is marked intentional rather than collapsible.
