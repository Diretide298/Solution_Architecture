Eight screens, one module, one contract. The source calls this a portal over artefacts that already exist — the 28 contract files are the documentation, so this platform is frontend scope rather than a contract gap. Northbridge Systems is the stand-in integrator: a ticketing reseller building against the public API.

Drawn against a domain with no workshop. Developer & API is one of CF-21's three unblocked-nowhere domains — 94 requirements, and the workshop has never been held. CF-135 records that the contract landed anyway and that the twelve domain-13 rows still open are all these eight screens. So the board is real design against real operations, and the commercial questions behind it — rate limits, licensing tiers, what certification costs — are CF-135c and still the client's to answer. Where a screen depends on one of those, it says so rather than inventing a number.

Replay is a range, not a row
An endpoint that was down for an hour needs the hour back, so replayEvents takes a window and an event type. Replays are marked as replays in the payload — an integrator has to be able to tell a re-delivery from a new sale.

What this board found. Four. The one operation P15-style gap tables would call missing is not missing: issueApiToken reaches no screen because it is a machine call — a developer's code exchanges a credential for a token, and a screen for it would be wrong. The gap table cannot tell a machine endpoint from a screen-backed one, and this is the case to say so out loud rather than draw a screen to satisfy a report. Three that are real: DEV-005 declares the delivery log as onAction when it is the reason the screen exists; DEV-006 has no operation for a developer to request a quota change, while setApiQuota sits staff-only on DEV-008; and DEV-003's credential-rotation overlap window is a number this drawing invented — CF-85's problem, one screen along.
