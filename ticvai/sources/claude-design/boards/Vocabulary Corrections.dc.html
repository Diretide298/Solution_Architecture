Eleven of them are audit trails and are right by accident of their titles. BP-006 is not a pattern. It is the layout a generator writes when nobody wrote one.

defect 2 Nothing in the vocabulary says this screen publishes vocabulary addition · 8 screens

Seven publish gates were filed alongside eleven read-only audit trails because both declare searchField · timeline. The components are all a screen has to say what it does, and none of them carries consequence: a screen that makes a draft live and a screen that reads what somebody else made live are indistinguishable in the vocabulary.

A component, not a template
A publish template was the other option, and one screen settles it. BO-094 Map Editor & Publish is a canvas that publishes — you place points on a plan and then make the plan live. BO-153 is a dashboard that publishes. A template can only be one of those, so publishing would force a layout on a screen whose layout is already decided by its content. A component composes with both.

The vocabulary already names reviewThenPublish as a pattern — draft, validate, preview, publish, with a diff at the review step. It has no component to hang the gate on, which is why the pattern is declared by two screens and the other eight publish from a primary button.

+ description: >
+ Making a draft live, with what it will
+ affect named before it happens.
+ states: [draft, validating, blocked,
+ publishable, publishing, published,
+ overridden]
+ requiredWhen: the screen calls an
+ operation that publishes, deploys
+ or activates
+ notes: >
+ `blocked` names what is wrong and
+ what to do — a disabled Publish with
+ no reason is the state operators
+ escalate.
+ `overridden` is a publish that went
+ past a warning; it is recorded,
+ because the person who authorised it
+ is the whole value of the record.
+ Saving is not publishing. A gate that
+ shares its button with save will be
+ pressed by somebody who meant to save.

defect 5 An audit trail is offering to create its first entry found while confirming · 11 screens

Every one of the eleven audit trails declares an emptyFirstRun reading Nothing configured yet. The action is to create the first … entry, and this state carries it. Nobody creates the first row of an immutable audit log by hand. On CMS-058 Compliance Evidence and ADM-296 Resale Ownership History the offer is worse than wrong — a screen that invites somebody to author evidence is a screen that should not have that button.

The vocabulary already draws the distinction the fix needs. emptyFirstRun is nothing exists yet and this person may create the first one; emptyNoResults is the data exists and the filter matched nothing. An audit trail with no events is neither: the record is complete and it is empty because nothing has happened. That is a third empty state, and it is the one timeline screens need.

The frame at BP-006 already drew this state and called it emptyNoEvents — drawn before the defect was found, because drawing the screen forced the question the YAML never asked. Adopt the name from the frame rather than inventing a second one.

What this changes downstream
Phase 1 loses a frame and gains a question
The BP-010 fold means the seventeen finance, stock and approval screens are served by the BP-001 frame already drawn, so Phase 1 draws nothing new for them. The five re-signatured screens leave BP-006 for patterns that already have frames.
Phase 2 assembles against 43, not 44
P08's 363 screens include the seventeen and three of the five. Regenerating before assembly is what keeps the P08 boards from carrying the mislabel into 363 frames, which is the whole argument for running this phase first.
The generator default outlives this pass
Twenty-three screens got a layout nobody wrote, and the same generator wrote the other 793. Re-signaturing these does not stop the next unsigned screen from becoming a dashboard with a timeline on it. Two checks belong on the schema: a screen whose only operation is list… cannot claim a verb in its title, and a layout nobody authored should fail rather than default.
