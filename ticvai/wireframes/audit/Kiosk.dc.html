Four changes. Set offlineCapable: true on P05 — the screens already behave as if it were, and the flag is the thing that is wrong. Write the offline state instead of excusing it. Label the primary button. And disable Cancel until the inquiry resolves or a member of staff takes it — there is no safe way for a guest to walk away from this screen alone.
The pattern under all thirteen findings
615 of 1,532 components — 40%, up from 38% before the fix — carry derived: true, generated from the operation list rather than drawn. All 178 orphan “Cancel” buttons are among them, and so is every unlabelled destructive button. A generator can read that an operation exists; it cannot read that voiding an order needs a question first, that a receipt cannot be printed before a payment, or that a guest must not be able to walk away from a charged card. That judgement is the missing layer — and it is missing in exactly one shape everywhere: when this product does ask, it asks the same question 39 times.
